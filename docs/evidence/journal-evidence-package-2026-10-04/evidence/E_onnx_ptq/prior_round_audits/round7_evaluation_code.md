## Main findings

1. **The cheap WER selector has a real sample-rate bug.** [eval_wer_cheap.py:71](<WSL_PROJECT_HOME>/scripts/eval_wer_cheap.py:71) passes the raw ONNX waveform directly to `whisper_model.transcribe(audio, language="en", fp16=False)`. The TTS waveform is 22,050 Hz. Installed [Whisper audio.py:122](<WSL_PROJECT_HOME>/env/lib/python3.10/site-packages/whisper/audio.py:122) expects array input at 16,000 Hz; only string paths invoke `load_audio` and FFmpeg resampling at lines 139–141. Thus the cheap selector interprets these samples at the wrong rate (duration factor 22050/16000 = 1.378125). Its model/scope rankings require a corrected validation run; historical rankings cannot establish the optimal PTQ scope. The 500-utterance evaluator passes a WAV path, so this particular bug does **not** apply to its WER calculation.
2. **The selector and main evaluator use different scorers and normalization.** Cheap selection uses `base.en`, an ASCII regex retaining apostrophes and replacing other punctuation by spaces, and auto-selects the Whisper device; the main evaluator uses `small`, CPU, English, and JiWER Unicode punctuation removal. Cheap failures receive a WER surrogate of 1.0; true WER can exceed 1.0, so this surrogate may rank failure above a valid but poor output. It saves aggregate WER without per-item transcripts/failure identities. Minimum fix: correct sample rate, freeze scorer and normalization, save item results, and report failures separately or reject failing configurations.
3. **Saved main WER is an arithmetic mean over utterances, not corpus WER.** All 2,000 saved per-utterance WER values were reproduced exactly from the stored reference/hypothesis transcripts using the code's normalization. These remain historical observations, not newly rerun experiments. Their macro percentages are 12.300292 / 11.350467 / 10.427437 / 11.236193 for baseline FP32 / baseline PTQ / MRF FP32 / MRF PTQ rerun. Corpus percentages from these same transcripts are 11.584941 / 10.690216 / 9.319840 / 9.908214, respectively. Do not substitute these numbers in the thesis without relabeling the aggregation; the main table can keep its existing macro values with an explicit definition.
4. **UTMOSv2 prediction itself is stochastic in the installed default path.** `create_model` defaults to `fusion_stage3`, fold 0, seed 42, with seed 42 selecting the checkpoint filename rather than seeding prediction RNG ([create.py:21](<WSL_PROJECT_HOME>/env/lib/python3.10/site-packages/utmosv2/_core/create.py:21), line 68). `configure_execution` sets phase `prediction`; `get_dataset` maps the config name to `SSLLMultiSpecExtDataset`, which calls both SSL and multispectrogram datasets. These unconditionally draw NumPy random 3-second SSL crops, 1.4-second spectrogram crops, and beta mixup in the prediction path. The `train`/`valid` branch only chooses the image transform; it does not gate these draws. Relevant sources: [fusion_stage3.py:73](<WSL_PROJECT_HOME>/env/lib/python3.10/site-packages/utmosv2/config/fusion_stage3.py:73), [ssl.py:46](<WSL_PROJECT_HOME>/env/lib/python3.10/site-packages/utmosv2/dataset/ssl.py:46), [multi_spec.py:49](<WSL_PROJECT_HOME>/env/lib/python3.10/site-packages/utmosv2/dataset/multi_spec.py:49), [_utils.py:37](<WSL_PROJECT_HOME>/env/lib/python3.10/site-packages/utmosv2/dataset/_utils.py:37). Neither main ONNX evaluation nor MRF-1386 PyTorch evaluation explicitly seeds NumPy. The latter's `torch.manual_seed(1234)` does not establish seeded UTMOS crops. `predict()` defaults to one repetition, despite a separate configuration field `inference.num_tta=5` used in another API path.
5. **ONNX inference is not explicitly seeded in the main or cheap evaluation.** The previously inspected four relevant graphs each contain two `RandomNormalLike` nodes without seed attributes. The main script has no `ort.set_seed`, no per-item random inputs, and uses nonzero noise scales `[0.667, 1.0, 0.8]`. Paired FP32/PTQ text lists therefore do not establish paired synthesis draws. Establish and record an actual repeatability policy before the final run; an identical seed alone should not be claimed to guarantee identical draws across changed graph structure or runtimes without checking it.

## Timing and saved pairing

[eval_onnx_ptq_500.py:63](<WSL_PROJECT_HOME>/scripts/eval_onnx_ptq_500.py:63) times only `sess.run(None, feed)[0]` using `perf_counter`, then divides by generated waveform samples / 22050. Session/model loading, text/phoneme preparation, output squeezing/casting, PCM/WAV conversion, file I/O, UTMOS and ASR are outside this interval. Batch size is one, provider is `CPUExecutionProvider`, default intra-op threads 2, inter-op threads 1, sequential execution. The saved means are means of utterance RTFs, not sum(time)/sum(duration). The script has no explicit warmup or repeated timing per utterance, no runtime/hardware/hash envelope, and no explicit malformed/NaN output guard before scoring.

There **are separate completed benchmark sources and logs**, `bench_vnni_baseline.py` and `bench_vnni_mrf.py`, using three warmups plus fifteen timed runs, five dataset rows and one/two threads. This does not retrofit warmups into the 500-utterance quality evaluations. These benchmark sources compute mean latency divided by the duration of only the final generated output while stochastic durations may vary. A final benchmark should save each latency with its corresponding audio duration, and separate cold-start and warmed measurements.

Stored reference texts match in order for baseline FP32/PTQ (500/500) and MRF FP32/PTQ (500/500). Baseline versus MRF shares only 21 unique texts. These are paired text comparisons within each branch; cross-architecture causality and paired stochastic draws are not established. All result JSONs only record `idx`, `text`, `asr_text`, `synth_time_s`, `audio_duration_s`, `rtf`, `utmosv2`, and `wer`; no model, manifest, waveform or scorer hash is embedded.

The current file is 818,531,314 bytes with SHA-256 `c8149d988e4bbf3f347e6966b5d769de347a5f8c59ffca1dc4bd4bf5b8585e57`. This establishes the historical path and the present file's hash; no run-time hash was saved. The config combines `facebook/wav2vec2-base` and `tf_efficientnetv2_s.in21k_ft_in1k`; the `predict_dataset` default is `sarulab`.

Current cached Whisper `small.pt` SHA-256 is `9ecf779972d90ba49c06d968637d720dd632c55bbf19d441fb42bf17a411e794`; `base.en.pt` is `25a8566e1d0c1e2231d1c762132cd20e0f96a85d16145c3a00adf5d1ac670ead`. Both match the installed package's expected checksum mappings. The saved main logs name `small`; its full historical path/hash is not in the saved result envelope. Whisper transcribe defaults include temperature fallback `(0,.2,.4,.6,.8,1)`, so `fp16=False` and English alone do not specify deterministic decoding. Freeze all decoding arguments and RNG policy for the new run.

UTMOS receives the original float waveform with `sr=22050`; `_prepare_data` correctly resamples to the config's 16000 Hz using Torchaudio. ASR receives the saved PCM16 WAV produced by BanhmiTTS `audio_float_to_int16`, which scales by `32767 / max(max_abs, .01)`. These are different amplitude/quantization representations of the generated signal, a methodology distinction that must be recorded. For final evaluation, use one explicitly documented persisted signal as the common source for both scorers and retain its hash.

Although UTMOS `predict` declares `remove_silent_section=True`, the installed implementation temporarily changes `cfg.dataset.remove_silent_section`, constructs a dataset holding that same config reference, then restores the field before DataLoader iteration. Under the default config (no original flag), the subsequent dataset getter sees `None`. Do not claim confirmed silence removal from the signature alone; this static discrepancy needs a focused preprocessing check if the final protocol requires removal. No prediction was executed to test it here.
